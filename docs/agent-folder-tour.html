Folder Guide — Internal

Inside the agent/ Folder

A plain-language tour of what each piece in src/agent/ does, and exactly where it hands off to the rest of the codebase. No code in this one — just the shape of it.

Scope — src/agent/ only Not covered here — the AI's written instructions in prompts/

01What this folder is

agent/ is the decision-maker. It reads a conversation, decides what should happen next, and either says something back or asks for a real capability — like "look up this doctor" — to be carried out.

The one thing worth holding onto: nothing in this folder knows the database exists. It doesn't import a database driver, doesn't write a query, and doesn't know a table name. When it needs real information, it hands a request to code that lives outside this folder and waits for a plain answer back.

02Its two doors to the rest of the app

In: one function call, carrying the conversation and who's asking. Out: either a message to show the patient, or a request for one of exactly four named actions — never anything more open-ended than that.

03A tour of what's inside

Nine small folders, each doing one job.

FolderWhat it does, in plain terms
service/ The front desk. This is the only file the rest of the app is allowed to call into. Everything else in agent/ is reached through it.
graph/ The wiring diagram for one turn of conversation. It says, in effect: "start by thinking, then check if an action was requested, do it if so, then think again — repeat until there's a plain answer."
nodes/ The actual steps that wiring diagram refers to: one step asks the AI to think, one step decides what happens next, one step carries out a requested action.
state/ The shared notepad for a single turn — who's asking, the conversation so far, and the answer as it's being built up. Every step reads from and writes to it.
tools/ The four specific things the AI is allowed to ask for: search doctors, check open times, book, cancel. Each is a small named wrapper — the real work happens outside this folder.
registry/ A simple phone book: given the name of a requested action, it looks up which wrapper actually handles it.
adapters/ A translator. It describes the four actions to the AI vendor in the exact shape that vendor expects, so the AI knows they exist and what to ask for.
providers/ The plug that connects to whichever AI vendor is actually doing the "thinking" (currently Groq). Switching vendors later only touches this one spot.
utils/ Small converters — mainly turning a saved database message back into the format the AI vendor expects, and back again.

(There's a tenth folder, prompts/, holding the AI's written instructions and personality. It's out of scope for this doc — it doesn't affect how the folder talks to the rest of the app, only what the AI chooses to say.)

04How one request moves through it

  1. It arrives through the front desk

    service/ is handed the conversation so far and who's asking. Nothing else in the folder is reachable from outside it.

  2. The wiring diagram starts

    graph/ kicks the loop off at its first step: think.

  3. The "think" step runs

    One node in nodes/ passes the conversation to providers/, which forwards it to the AI vendor. The reply is either something to say, or a request for one of the four actions in tools/.

  4. A decision step checks the reply

    Another node in nodes/ looks at what came back and decides: was an action requested, or is this a finished answer?

  5. If an action was requested, it's carried out

    A third node in nodes/ uses registry/ to find the right wrapper in tools/, runs it, and gets a plain result back. That wrapper is what actually calls out through the folder's second door to Booking Service / Doctor Service.

  6. Think again

    The result goes back to step 3, and the loop repeats until the AI produces a finished answer instead of another action request.

  7. It leaves through the front desk

    service/ hands the finished answer back to whoever called it in — agent/'s job for this turn is done.

05Why it's organized this way

Three plain benefits fall out of keeping the folder this shape:

  • One door in, one door out. Nothing reaches into the middle of this folder from outside — everything goes through service/ coming in, and tools/ going out.
  • The AI vendor can be swapped without touching booking logic. Because only providers/ knows which vendor is in use, replacing Groq with something else later never requires changing how bookings work.
  • New abilities don't require touching the wiring diagram. Adding a fifth action later means adding one new file to tools/ and registering it — graph/ and nodes/ stay exactly as they are.
In short: this folder decides what to do and when — it never decides how data gets stored or fetched. That part always lives one door away, outside agent/.
